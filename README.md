# 모키 커피바 — RAG 키오스크

서울대 빅데이터 핀테크 AI 고급 전문가 과정 13기 · AI응용 실습문제(RAG) · **4조**

좌석 태블릿에 대고 말로 주문하는 커피바 키오스크. 메뉴 지식은 RAG로 공급한다.

**4조 작업 저장소입니다.** 코드·데이터·프롬프트·문서가 모두 여기 있습니다.

| 팀 | 담당 | 고칠 곳 |
|---|---|---|
| 데이터 | 류성환 · 오승재 | `data/moki_data.xlsx` |
| 프롬프트 | 안나량 · 이주연 | **`prompts/*.md`** — 파이썬 안 건드려도 됩니다 |
| 개발 | 박채원 · 신기훈 | `src/` · `app.py` |

문서: [컨셉](docs/01_컨셉.md) · [HTI](docs/02_HTI.md) · [회의록](docs/03_회의록.md) · [일정](docs/04_일정.md)

```
손님 입력 → 질의 재작성 + 의도 분류 (LLM 1회) → 하이브리드 검색 → 답변 생성 (LLM 1회)
                                              ↘ 장바구니·가격 계산 (코드)
```

## 빠른 시작

```bash
git clone https://github.com/Shin-kihoon/moki-kiosk.git
cd moki-kiosk
pip install -r requirements.txt

cp .env.example .env        # 열어서 OPENAI_API_KEY 채우기
python scripts/build_index.py   # 한 번만. 문서 61개 임베딩
streamlit run app.py
```

`.env` 는 깃에 올라가지 않는다. **조교님 공용 키를 커밋하지 말 것.**

## 💸 비용 주의

조교님 공용 API 키를 쓴다. 호출을 줄이려고 아래를 넣어 두었다.

| 장치 | 효과 |
|---|---|
| 인덱스 디스크 저장 (`index/`) | 앱 켤 때마다 61개 재임베딩 → **0회** |
| 질의 재작성 + 의도 분류 통합 | 턴당 LLM **3회 → 2회** |
| 답변 캐시 (`.cache/answers.json`) | 같은 질문 재실행 **0회**. 시연 리허설이 공짜 |
| 질문 임베딩 캐시 | 같은 질문 재검색 **0회** |
| 범위 밖 질문은 검색 생략 | "오늘 날씨" 같은 질문에 임베딩·검색 비용 안 씀 |
| `max_tokens` 제한 | 출력 토큰이 입력보다 비싸다 |
| 대화 이력 최근 4턴만 | 턴이 쌓여도 입력 토큰이 늘지 않음 |
| **MOCK 모드** | `MOKI_MOCK=1` 이면 API를 한 번도 부르지 않는다. 화면 작업용 |

```bash
MOKI_MOCK=1 streamlit run app.py     # API 0원으로 화면 개발
```

## 프롬프트 팀에게

프롬프트는 코드에서 빼내 `prompts/` 폴더의 마크다운으로 두었습니다.
**파이썬을 열 필요 없이 .md 파일만 고치면 됩니다.**

| 파일 | 역할 |
|---|---|
| `prompts/system.md` | 응대 규칙·캐릭터·가드레일 |
| `prompts/router.md` | 질의 재작성 + 의도 분류 (JSON 키 이름은 바꾸지 마세요) |
| `prompts/offtopic.md` | 범위 밖 질문 응대 |

고친 뒤 `streamlit run app.py` 를 다시 켜면 반영됩니다.
실패 사례는 `python tests/run_checks.py --ids Q05 Q10` 식으로 특정 질문만 돌려 확인할 수 있습니다.

## RAG 문서 설계

**메뉴 1개 = 문서 1개.** 글자 수로 자르지 않는다. 1,000자씩 기계적으로 쪼개면
아메리카노의 설명과 가격이 다른 조각으로 찢어져, "아메리카노 얼마예요?"에
가격이 안 따라온다.

다만 **검색용 글과 모델에 넘기는 글을 나눴다.**

| | 내용 |
|---|---|
| `page_content` (검색용) | 이름·별칭·분류·한 줄 설명·태그·맛 점수 |
| `metadata["full"]` (근거용) | 가격표·영양·카페인·알레르기·영문 안내 전체 |

전부 한 문서에 넣었더니 임베딩이 평균값으로 흐려져 "하이볼"로 검색해도
위스키 하이볼이 거리 1.228로 밀려났다. 분리 후 1.072로 올라왔다.

문서 61개 = 메뉴 33 · 원두 3 · 옵션 6 · 매장정책 19

## 하이브리드 검색

순수 벡터 검색은 짧은 한국어 질문에 약하다. 실측으로 확인한 것:

| 질문 | 벡터만 | 하이브리드 |
|---|---|---|
| 아아 하나 | 약과 2개 ✗ | 아메리카노 ✓ |
| 하이볼 | 기준값 초과로 버려짐 ✗ | 유자·위스키 하이볼 둘 다 ✓ |
| 두유로 바꾸면 돈 더 내요? | 원두 선택 ✗ | 우유 변경 ✓ |
| 임산부가 마실만한거 | 라거 맥주 ✗ | 영양·카페인 + 저카페인 메뉴 ✓ |

1. **규칙 매칭** — 별칭·정책 키워드·옵션 키워드가 문자열로 겹치면 바로 집는다. API 호출 0회
2. **맛 점수 필터** — "산미 적고 고소한"을 1~5 점수 조건으로 바꿔 거른다
3. **벡터 검색** — 위가 놓치는 의미 기반 질문 담당. 거리 기준값(기본 1.15)을 넘으면 버린다

## 지켜지는 규칙

데이터팀 `매장정책` 시트를 코드와 프롬프트 양쪽에 넣었다.

- **가격은 코드가 계산한다** (P11). 모델은 계산 결과를 전달만 한다
- **주류는 직원 확인 전까지 `pending_staff_check`** (P15). 손님 자기신고는 확인이 아니다
- **모호한 이름은 담지 않는다.** "하이볼 하나" → 두 하이볼을 보여주고 되묻는다 (Q47)
- **수량 1~10 정수만** (P11). 0이나 음수를 1로 자동 보정하지 않는다
- **온도·크기를 임의로 정하지 않는다** (P03)
- **기프티콘·적립·분할결제·실시간 대기는 미지원** (P07). 됐다고 답하지 않는다
