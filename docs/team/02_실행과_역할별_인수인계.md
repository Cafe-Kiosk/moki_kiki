# 실행과 역할별 인수인계

기준일: 2026-10-15. 다음 실행 방법은 최신 발표가 설명하는 **수정 후보**용입니다.
main 앱 실행 방법과 섞으면 프롬프트 파일·상태 구조·시험 명령이 달라집니다.

## 발표와 같은 버전 실행하기

다음은 기존 작업 폴더와 별도 폴더에 받는 방법입니다. 키와 비밀번호는 본인에게 허용된 값을 로컬에서 설정합니다.

```bash
git clone --branch codex/complete-moki-order-flow https://github.com/Cafe-Kiosk/moki_kiki.git moki-demo
cd moki-demo
git rev-parse HEAD
# 이번 발표·검토 기준: bb5b0a2a8392fc59447ff5b7ced5e010ef5a299f
git switch --detach bb5b0a2a8392fc59447ff5b7ced5e010ef5a299f
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock.txt
cp .env.example .env
# .env의 OPENAI_API_KEY를 설정, MOKI_MOCK=0 확인
python -m streamlit run app.py --server.port 8510
```

`http://127.0.0.1:8510/`은 각자 컴퓨터의 앱입니다. PDF/PPT의 주 시연 버튼도 이 주소이므로 서버를 먼저 실행해야 합니다.
`git switch --detach`는 검토 커밋을 고정해 보는 용도입니다. 변경 작업은 해당 커밋에서 새 브랜치를 만들어 수행합니다.
이번 문서 작업에서 새 컴퓨터 설치나 전체 실제 API 재시험은 하지 않았습니다.

화면만 확인할 때는 `MOKI_MOCK=1 python -m streamlit run app.py --server.port 8510`을 사용합니다.
실제 발표에는 MOCK를 해제하고 현재 API 사용 가능 여부를 확인합니다. 모델 인증 성공만으로 크레딧·대화 성공이 보장되지는 않습니다.
환경변수는 `.env`보다 우선할 수 있으므로 오래된 설정이 있으면 로컬에서 정리한 뒤 서버를 재시작합니다.

## 네 가지 정보는 역할이 다릅니다

| 정보 | 역할 | 혼동하면 생기는 문제 |
|---|---|---|
| RAG 자료 | 판매 메뉴·옵션·정책·성분의 근거 | 검색됐다는 이유만으로 주문 처리 완료를 말함 |
| 대화 이력 | ‘작은 걸로요’ 같은 후속 발화의 맥락 | 앞 주문 조건을 잃거나 새 주문으로 오인 |
| 현재 장바구니 | 선택 옵션·수량·현재 합계 | 모델의 추측을 실제 주문으로 표시 |
| 확정 주문 | 확인한 내역·번호의 스냅샷 | 추가 주문이 이미 확정한 주문을 덮어씀 |

라우터가 행동을 JSON으로 해석하고, 검색기는 필요한 문서를 찾고, 주문 코드는 허용 여부·금액·상태를 검증합니다.
답변 모델에는 검색 근거와 실제 코드 결과를 함께 전달합니다. FAISS 검색은 로컬이며 요청 해석·질문 임베딩·답변 생성은 실제 모드에서 API를 사용할 수 있습니다.
캐시는 입력·상태·모델 조건에 따라 재사용됩니다. 같은 문장을 입력한다고 모든 호출이 반드시 0회가 되는 것은 아닙니다.

## 데이터 담당

- 기준 원장은 `data/moki_data.xlsx`입니다. 메뉴·판매 구성·원두·옵션·정책·한영 정보가 연결됩니다. [v4 안내](data/01_팀_사용안내.md)를 먼저 확인합니다.
- 메뉴 33개와 판매 구성 52개는 다른 개수입니다. 검증질문 47개는 평가용이며 검색 근거에 넣지 않습니다.
- `docs/team/data/mokey_data.json`과 `rag_documents.jsonl`은 데이터팀 v4 전달 스냅샷입니다. 엑셀 변경이 자동으로 이 파일에 반영되지 않습니다. 앱은 전달 JSONL 대신 엑셀에서 문서 61개를 생성합니다.
- 삭제한 메뉴·옵션은 가격표·별칭·추천·페어링·문서·인덱스에서도 함께 제거합니다. 새 데이터를 옛 인덱스에 덧붙여 섞지 않습니다.
- 판매 단위(약과 2개 1접시·쑥인절미 4개 1접시), 공통 별칭 ‘하이볼’, ICED와 얼음 여부를 구분합니다.
- 데이터/검색 문장을 바꿨다면 데이터 검사 → 인덱스 갱신 → 영향 질문 시험을 함께 기록합니다. 인덱스 갱신은 유료 API를 사용할 수 있습니다.

## 프롬프트 담당

| 파일/계약 | main | 수정 후보 |
|---|---|---|
| 응대 본문 | `prompts/system.md` | `prompts/system.txt` 우선, `system.md`는 안내 |
| 요청 해석 | 단일 intent·order_items 중심 | `actions` 목록, `quantity_mode`, 누락 조건, 세션 상태 |
| 검증 | 기존 라우팅 구조 | Pydantic 모델과 `prompts/runtime_schema.json` |
| 원안 보존 | 기존 프롬프트 | `prompts/team_reference/` |

수정 후보의 시스템 본문은 프롬프트팀 원안과 일치하지만 코드가 실행 조건을 추가하므로 전체 시스템 메시지와 동일하다는 뜻은 아닙니다.
질의 재작성과 복합 행동 해석은 통합 라우터 한 호출로 연결했습니다. 원안의 모든 함수·필드·few-shot을 그대로 실행한다고 설명하지 않습니다.
출력 키를 바꾸려면 `src/router.py`·`src/kiosk.py`·실행 스키마·관련 시험을 함께 바꿉니다. 프롬프트 파일 변경 후 프로세스를 재시작합니다.

반드시 유지할 행동은 추천만으로 담지 않기, 모호한 메뉴·누락 조건 되묻기, 근거 없는 가격/인기/재고 만들지 않기,
‘총 두 잔’과 ‘두 잔 더’ 구별하기, 처리 성공 전 완료를 말하지 않기, 언어 변경 중 주문 조건 유지하기입니다.

## 개발 담당

- `src/cart.py`: 수량 1~10 정수·메뉴별 옵션·추가 샷 0~2·금액·확정 스냅샷을 검증합니다.
- `src/kiosk.py`: 복합 요청·미완료 요청·한 잔 분리 수정·취소 확인·되돌리기·확정 후 추가 주문을 연결합니다. 오류가 나면 일부 쓰기만 반영되지 않도록 합니다.
- `src/router.py`: 외부 모델 출력의 스키마를 검증합니다. 모델이 준 ID·수량·옵션을 그대로 신뢰하지 않습니다.
- `src/index.py`·`src/documents.py`: 데이터·문서·모델·인덱스 파일의 일관성을 확인합니다. MOCK 벡터를 실제 인덱스에 저장하지 않습니다.
- `app.py`: 화면의 선택값과 실제 장바구니가 일치해야 합니다. 고객의 체크를 직원 승인으로 취급하지 않습니다.
- 저장 FAISS에는 역직렬화가 포함되므로 검토한 저장소의 인덱스를 사용합니다. 출처가 다른 파일을 임의로 교체해 로드하지 않습니다.

## 서로 전달할 최소 자료

| 보내는 파트 | 전달할 것 | 받는 파트의 완료 확인 |
|---|---|---|
| 데이터 → 개발/프롬프트 | 데이터 버전·변경 ID·판매 단위·허용 옵션·기대 질문 | 같은 데이터로 검색 근거와 주문 금액 확인 |
| 프롬프트 → 개발 | 실제 입력/출력 계약·예외 응답·상태 조건 | 스키마 검증, 후속 발화, 복합 행동 확인 |
| 개발 → 발표/검증 | 커밋·실행 명령·검증 결과·미지원 목록 | 같은 버전에서 답변·근거·주문 상태 재현 |
| 발표 → 제출 담당 | 발표 PDF·프로그램 버전·설치/시작 안내 | 파일 열기·실행·실제 제출와 접수 확인 |

## 오류가 나면

| 증상 | 확인할 것 |
|---|---|
| `openpyxl` 등 모듈 없음 | 현재 파이썬과 설치 환경 확인, 해당 버전 requirements 설치 |
| 키 인증 성공 후 429/크레딧 오류 | 현재 키의 사용 가능 상태 확인, 실패를 성공 시연으로 말하지 않기 |
| 저장 인덱스 불일치 | 데이터·문서·모델 버전 대조, 확인 후 필요할 때만 재생성 |
| 발표 버튼이 안 열림 | 8510 서버가 먼저 실행됐는지 확인 |
| 문서는 최신인데 공유앱 동작이 다름 | 배포 브랜치·커밋 확인, 로컬 후보와 별도 상태로 취급 |

코드 병합·배포·최종 채택은 이번 문서 업로드에서 수행하지 않았습니다.
