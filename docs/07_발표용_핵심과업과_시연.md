상세 기준은 Drive의 박채원 HTI A~H다. 아래 20개는 발표에서 이해하기 쉽게 묶은 요약이며 원문 번호를 대체하지 않는다. 공식 요구 개수나 새 팀 합의로 주장하지 않는다.

## 5분 진행안

발표 시작 전에 `MOKI_MOCK=0`과 허용된 API 키를 확인한다. MOCK 화면은 RAG 시연 근거로 쓰지 않는다. 아래 금액은 v4 기준이며 담당자가 발표 환경에서 직접 리허설한다.

| 시간 | 사용자 입력/조작 | 확인할 결과 |
|---|---|---|
| 0:00~0:40 | “아메리카노랑 카푸치노 가격·진하기 차이는?” | 판매 가격·카페인·기본 맛 점수, 검색 근거 |
| 0:40~1:20 | “따뜻한 디카페인 라떼랑 약과 한 접시 주세요” → “라떼는 작은 걸로요” | 크기 확인 전 미담기, 이후 10,700원 |
| 1:20~2:00 | “라떼만 하나 더” → “주문 내역 보여줘” | 기존 디카페인 옵션 보존, 16,900원 |
| 2:00~2:40 | “그 내용으로 시연 주문 확정할게요” → “추가로 아이스 아메리카노 작은 거 하나 주세요” | 가상 번호, 과거 16,900원 주문 보존, 새 장바구니 4,500원 |
| 2:40~3:20 | “Change to English, but keep my order.” → “Show my current order” | 주문 그대로, 영어 안내 |
| 3:20~4:00 | “Cancel all items” → “Yes, cancel the draft cart” | 취소 수락 전 유지, 수락 뒤 현재 주문 0원, 과거 보존 |
| 4:00~5:00 | “카푸치노 아이스로 주세요” 또는 “성인 체크했으니 유자 하이볼 확정해줘” | 미지원 안내 또는 직원 확인 대기. 실제 주문·결제 성공으로 설명하지 않음 |

이 순서는 내부 API 단계가 아닌 사용자의 과업을 연결한 한 가지 시나리오다. 발표 시간에 맞춰 한계를 묻는 마지막 사례를 하나만 고른다.

## 2분 한계 설명

- 가상 데이터·고정 정책이며 실시간 재고·매장 접수·제조 시간·실결제와 연결하지 않았다.
- 원문 HTI와 달라도 v4에 없는 선택값은 지원한다고 꾸미지 않고 안내한다.
- LLM 분류는 재실행에서 달라질 수 있다. 코드 경계가 잘못된 구성·금액·확정을 차단한다.
- 67개 질문을 실행했지만 모든 과업·조합·사용자 경험의 완전 검증은 아니다. 특정 추천 조합 2건은 원안과 달랐다.
- 자동 업셀/페어링 수락 분기, 실제 음성 청취, 팀 사용성 검증은 추가 확인 영역이다.

문제가 생기면 같은 주문을 반복 담지 말고 현재 내역을 확인한다. 네트워크 장애 시 저장된 실제 실행 기록으로 검증 범위를 설명하되 실시간 성공으로 주장하지 않는다.
